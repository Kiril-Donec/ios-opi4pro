# Пробный запуск XNU на Orange Pi 4 Pro — вручную, без прошивки

**Готовность:** первый A733-специфичный XNU payload, Stage0 и U-Boot
`.scr` прошли сборку и тесты GitHub Actions.
**XNU на самой плате ещё не запускался.** Первый запуск может зависнуть или
показать исключение на HDMI. Это не готовая iOS.

Проверенная сборка: [GitHub Actions 39299998464](https://github.com/Kiril-Donec/ios-opi4pro/actions/runs/39299998464),
артефакт [`a733-firstboot-EXPERIMENTAL-no-flash`](https://github.com/Kiril-Donec/ios-opi4pro/actions/runs/39299998464/artifacts/12211572340).
Новые коммиты могут давать другие номера сборок.

## Важно для единственной рабочей microSD

- **Не записывай новый .img на карту**, не форматируй её и не заменяй
  штатные `boot.scr`, `boot.cmd`, U-Boot, SPL, DTB или Linux-ядро.
- Перед тестом желательно сделать побайтовую резервную копию карты.
  Без бэкапа есть риск потерять данные при любой непредвиденной проблеме.
- Тест запускается из **интерактивной командной строки U-Boot**, а не
  автоматически. Если нет способа остановить автозагрузку и увидеть
  приглашение `=>` (через HDMI/клавиатуру либо UART), **остановись**.
- Ничего из описанных U-Boot команд не пишет на microSD. После
  зависания выключение питания и обычная перезагрузка должны снова
  запускать прежнюю систему, **если её загрузочные файлы не меняли**.

## Подготовка файлов

Скачай ZIP артефакта в разделе **Artifacts** указанной сборки.
Внутри нужны три файла:

| Файл внутри ZIP | Путь на первом ext4-разделе, читаемом U-Boot |
| --- | --- |
| `build/stage0.uimg` | `/ios-a733/stage0.uimg` |
| `build/a733-xnu.payload` | `/ios-a733/a733-xnu.payload` |
| `build/a733-xnu-one-shot.scr` | `/ios-a733/a733-xnu-one-shot.scr` |

Все три файла скопируй в **новую** папку `ios-a733` на уже существующем
ext4-разделе загрузки. Не путай его с системным разделом Linux, если
разделов несколько. Скрипт ожидает, что на `mmc 0:1` уже лежит
`/dtb/allwinner/sun60i-a733-orangepi-4-pro.dtb`, используемый
рабочей сборкой. **Не перезаписывай DTB ради этого теста**.
Отдельная ADT включена внутри самого XNU payload.

Если не уверен, где этот раздел, сначала покажи `lsblk -f`,
`findmnt` и список файлов в существующей загрузочной папке.
Без проверки путь не угадывай.

## Разовый запуск в RAM

После того как проверил доступ к U-Boot и наличие файлов, прерви
автозагрузку и в приглашении `=>` выполни по одной строке:

```text
mmc list
mmc dev 0
ext4load mmc 0:1 0x44000000 /ios-a733/a733-xnu-one-shot.scr
source 0x44000000
```

Если `mmc dev 0` или `ext4load` сообщает ошибку, **не выполняй
`source`**. Скрипт использует жёстко заданное `mmc 0:1`; на другом
устройстве его сначала надо адаптировать.

Скрипт читает Stage0 в `0x42000000`, существующий DTB в
`0x43000000` и XNU payload в `0x52000000`. Он ставит указатели
на payload в *копию FDT в оперативной памяти*, после чего выполняет
`bootm`. Он **не меняет** сохранённое окружение U-Boot и не делает
операций записи на карту.

## Что сфотографировать

1. Последний экран перед зависанием, включая сообщения U-Boot или Stage0.
2. Если есть `FDT HIGH RAM UNSAFE` — это ожидаемый возможный стоп:
   статический vendor DTB описывал лишь 512 МиБ, а XNU нужен проверенный
   участок памяти выше 4 ГиБ. **Не обходи эту проверку вручную**.
3. Если появился ранний маркер XNU, текст XNU, `panic` либо исключение
   с `ESR/ELR/FAR` — это и есть важный результат для следующего исправления.

**Пока не стоит перепрошивать единственную SD-карту ради этого эксперимента.**
Текущая цель — получить первый факт выполнения XNU на Cortex-A76 и
возможность безопасно вернуться к рабочему загрузчику.
